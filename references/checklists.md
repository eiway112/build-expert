# 三张检查表

> 用法：**打印出来逐条过**，不要靠记忆。
> 开工前那张决定项目成败；收工前那张决定成果保不保得住；中间那张管住"改坏了"这个头号风险。

---

## 表一 · 开工前 8 问（没答完不要动笔）

| # | 问题 | 答不出来的后果 |
|---|---|---|
| 1 | 这个领域**答错了有后果**吗？（会有人照它干活吗） | 没后果就不必用这套，成本不划算 |
| 2 | **权威源**在哪？现在拿得到吗？（能打开、能引用） | 拿不到 ⇒ 引用纪律空转，做出来是普通知识库 |
| 3 | **谁拍板**？禁入清单和口径分歧由谁定？他愿意参与吗？ | 没有 ⇒ 错了没人纠，只能靠 AI 自证 |
| 4 | **禁入清单**写下来了吗？（哪四类东西绝对不许进来） | 没写 ⇒ 商业值/算法/拼接会慢慢渗进来，且无人察觉 |
| 5 | **文件分层**定了吗？哪个文件是"唯一定义点"？ | 没定 ⇒ 同一口径写两遍，迟早分叉 |
| 6 | **会漂移的量**列出来了吗？（版本号 / 条目数 / 日期 / 行号） | 没列 ⇒ 它们会被写死进脚本，下次变更即误报 |
| 7 | **执行环境**给得了四能力吗？（读文件 / 跑脚本 / 版本控制 / **开独立会话**） | 读文件 / 版本控制缺任一 ⇒ 只能做前三个环节；跑脚本缺 ⇒ ④ 人工过表；独立会话缺 ⇒ ⑦ 降级并标注 |
| 8 | **时间预算**里，④ 门禁 + ⑦ 验证**单独估过工时**吗？ | 没单独估 ⇒ 这两块会被系统性低估，最后以"没时间"砍掉的正好是它们 |

> 第 1、2、3 问任一为否，或第 7 问中**读文件 / 版本控制**缺任一 ⇒ **明确说明不适合**，别硬做。第 7 问只缺跑脚本或独立会话 ⇒ **可以继续，但按 ④ / ⑦ 的降级路径走并标注**，不标注等于默认通过。第 8 问为否，把"这包只能当参考资料、不能当依据"提前说清。

## 表二 · 动手改文件前 3 问（每次改之前问一遍）

| # | 问题 | 三秒钟的事，但省掉最多的返工 |
|---|---|---|
| 1 | **这次改完，我打算怎么"回读"确认它真的变了？** | 命令成功 ≠ 状态变更。想不出回读方式，就先别改 |
| 2 | **这次是替换式还是追加式？** | 修一句话必须**先删旧句**。追加式修改会留下两句矛盾的话并存 |
| 3 | **改的是文件名 / 路径 / 关键值吗？** | 是 ⇒ 先全仓检索引用面，列出所有硬编码引用，一起改，改完跑一遍构建/校验 |

> 补充：**改动前先记下既有的检查集合**（现有的校验脚本、回归用例）。改完全量重跑，不是只跑你新加的那条路 —— 新增的检查/监听/中间件会改变既有流程的输入。

## 表三 · 收工前 10 条（说完"完成了"之前必须全过）

| # | 检查项 | 怎么算过 |
|---|---|---|
| 1 | 每个"已完成"，都**回读了产物**吗？ | 读文件内容 / 修改时间 / 数据记录，不是看命令回显 |
| 2 | 新加的闸门**注入过缺陷**吗？ | 塞一个错进去 → 退出码非零，且报的是预期条目 |
| 3 | 检查脚本**有退出码**吗？失败真的非零吗？ | 只打印不退出 = 假闸门，补上 |
| 4 | 所有**会漂移的数字**都是动态取值的吗？ | 全文搜版本号/条目数/行号字面量，命中即改 |
| 5 | 改过的规则，用**含近义词的关键词表**全仓重扫过吗？ | 扫到 0 命中，才算收敛 |
| 6 | 宣称面的数字，**安装者能自己数出来**吗？ | 每一条都能复现；不能的从宣称面拿掉 |
| 7 | **私有信息扫描**过了吗？ | 本机路径 / 真实姓名 / 客户名 / 单位名 / 密钥；有命中先脱敏 |
| 8 | 记忆 / 台账**进版本管理**了吗？ | 只落在本地临时目录、没入库的，等于没记 |
| 9 | **全量回归**重跑过吗？ | 跑全部既有检查，不是只跑新增路径 |
| 10 | 本次发现但**没修的问题，登记进台账**了吗？ | 写"已知未修"不算 —— 没登记 = 没立项，下次没人会捡 |

> **第 2、3、9 条是最常被跳过、也最常翻车的三条。** 跳过它们的代价是：闸门在，但拦不住任何东西。

## 附 · 三类坑速查（按坑的类别，不是按表面现象）

| 类 | 典型表现 | 应对（一句话） |
|---|---|---|
| **A 内容层** | 只增不减、新旧句并存；数字写死；同族不同步 | 替换式修改；动态取值；改后带近义词重扫 |
| **B 机制层** | 闸门无退出码；检查器零接线；全绿当成有效；零命中无对照 | 注入回验；发现 0 个检查对象即 FAIL；零命中先做阳性对照 |
| **C 工具层** | 本机命令的编码/路径/行尾坑 | **进技能文件，不靠记忆** —— 同类坑复发 3 次以上就说明它必须被写下来 |

> **C 类坑的判据**：一个坑如果第二次出现时你还得重新想一遍，它就该被写进技能或手册。靠"这次记住了"是记不住的。
