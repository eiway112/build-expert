# 断言模式库（17 条）

> **这是什么**：把"要保证的事"翻译成"机器能判的检查"的 17 个成熟套路。
> **怎么用**：挑出你这个项目需要的（一般 5~10 条够用），按「怎么套」填空写进你的检查脚本。
> **注意**：可复用是**模式**（怎么判），不是代码。具体判什么，必须按你自己的知识结构重写。
> 本文件不含任何特定领域内容。

---

## P-01 阴性失效拦截

- **判据**：当检查对象数量 = **0** 时报 FAIL（不是 PASS）。
- **防的是**：文件被删空、目录改名、正则失配 —— 检查器"没东西可查"时静默返回全绿。
- **怎么套**：
  ```
  发现 {对象类型} 数量为 0 时：报 FAIL，报错文案写清"未发现任何 {对象}，
  可能是路径失效或对象被删；此为阴性失效，不等于通过"。
  ```
- **误用对照**：写成 `if count == 0: print("ok")` —— 这是把"没有可检查的东西"当成了"没有问题"。

## P-02 假闸门体检

- **判据**：检查脚本**必须自带退出码**；发现失败即返回非零。只打印结果、退出码恒为 0 的脚本不算闸门。
- **防的是**：闸门看起来在跑，其实拦不住任何东西。
- **怎么套**：
  ```
  结尾固定：sys.exit(1 if 失败项数 else 0)
  交付前自测两个方向 —— 正常对象 → 0；故意改错一处 → 非零。
  ```
- **误用对照**：脚本里 `print("FAIL: ...")` 打了一屏，最后 `return 0`。

## P-03 缺陷注入自证

- **判据**：每个新闸门配一条"注入缺陷 → 必须报错，且报的是预期的那一条"的验证记录。
- **防的是**："全绿"被当成闸门有效的证据。全绿只证明当前内容过得了。
- **怎么套**：
  ```
  注入项：{往哪个文件的哪类位置，塞一个什么样的错误}
  期望：退出码非零，且报错编号 = {X}
  实测：{退出码}；报错编号 = {Y}；结论 {一致 / 不一致}
  ```
- **误用对照**：只跑一遍看是全绿就宣称"闸门已验证"。

## P-04 阳性对照

- **判据**：下"零命中 / 零问题"的结论之前，先用一个**已知应命中的对象**跑同一判据，它必须命中。
- **防的是**：判据本身失效（路径写错、正则失配、编码问题）伪装成"对象干净"。
- **怎么套**：
  ```
  对照对象：{一个已知存在问题的最小样本}
  期望：命中（≥1）；实测：{N}
  对照通过后再看目标对象结果，否则结论作废。
  ```
- **误用对照**：脚本对不存在的路径也返回"零命中"，于是把"文件名敲错"读成了"目标干净"。

## P-05 派生量动态取值

- **判据**：会随时间变化的量（版本号 / 文件数 / 条目数 / 行号 / 基线值）**不许写成字面量**，必须从定义点读或正则现取。
- **防的是**：源文件一升级，检查脚本就误报；且没人分得清"是脚本过期"还是"真出问题"。
- **怎么套**：
  ```
  禁止：if version == "1.2.0":            # 下次升版即失效
  改为：v = 从 {某文件} 解析实际版本值；if v != 期望值: ...
  ```
- **误用对照**：把一个"不存在的编号"写死进测试用例当反例，结果那个编号后来真被登记了 —— 反例变成了合法值，检查却仍报错。

## P-06 单一定义点 + 引用式

- **判据**：每个术语 / 口径只在一处定义；其他文件一律引用式指回。配套断言守「头部声明 = 最新记录」。
- **防的是**：同一口径在两处各写一遍，改一处漏一处，最终分叉。
- **怎么套**：
  ```
  定义点：{文件:章节}（唯一）
  其余位置写法：见 {文件} §{章节}
  断言：文件头部声明的版本/条目数 == 该文件末尾记录的最后一条
  ```
- **误用对照**：两个文件都写了完整口径，其中一份更新了，另一份还是旧的。

## P-07 同族收敛扫描

- **判据**：改一条规则后，用**含近义变体**的关键词表全仓重扫，并把命中清单逐条处理。
- **防的是**：只搜"自己想到的词"，实际残留用的是别的说法。
- **怎么套**：
  ```
  关键词表：{主词} + {它的近义写法 2~4 个}
  扫描范围：{全仓路径}（排除历史记录类文件）
  输出：命中 {N} 处 → 逐处处理并复扫至 0
  ```
- **误用对照**：改前扫一遍发现 3 处就动手，改完不扫 —— 真正漏掉的第 4 处用的是同义说法。

## P-08 替换式修订

- **判据**：修改一句话 = **先删旧句、再加新句**，不许只追加。
- **防的是**：新旧两句并存、互相矛盾，且两份都在"门禁全绿"下合法存在。
- **怎么套**：
  ```
  改动前：记录旧句原文（{旧句}）
  改动后：回读确认旧句出现次数 = 0，新句出现次数 = 1
  ```
- **误用对照**：把"新增说明"插在原句后面，原句没删 —— 阅读者不知道哪条作数。

## P-09 锚点落语义位置

- **判据**：注入 / 替换的锚点必须落在**目标语义位置**，并断言命中数、说得出"改的是第几行、那行属于哪一类行"。
- **防的是**：锚点在别处也命中（如历史记录、示例文本），脚本取了第一个，静默改错地方。
- **怎么套**：
  ```
  锚点：{待匹配文本}
  期望命中：{N} 处，位置 = {文件:行号范围}
  实测命中：{M}；若 M != N → 中止并人工核对，不许取首个命中继续
  ```
- **误用对照**：用"找首次出现"的方式改文，结果改的是一段历史记录里的同类句子。

## P-10 引用三件套齐备

- **判据**：每条判据/结论必须同时挂 **来源条款 + 核验层级 + 时效戳**，缺一即不合格。
- **防的是**：结论看着专业，但追不回是哪一条、还算不算数。
- **怎么套**：
  ```
  来源条款：{标准/法规编号 + 条款号}
  核验层级：{现行有效 / 已发布未生效 / 非条文本体 / 经验值}
  时效戳：{最近核验日期 + 下次复核日期}
  ```
- **误用对照**：只写了标准编号，没写条款号，也没写是哪个版本。

## P-11 时效戳分档

- **判据**：按**来源性质**定复核周期，分两档；档位规则只写在一处（定义点），其余回读。
- **防的是**：一刀切周期 —— 短了对稳定源是浪费，长了高风险源会过期。
- **怎么套**：
  ```
  短档（{条件 A：如来源为全文强制性文件}）：{复核周期}
  长档（{其余全部来源}）：{复核周期}
  规则定义点：{唯一位置}
  ```
- **误用对照**：对所有来源用同一个周期，高风险源长期未核。

## P-12 禁入清单机检

- **判据**：把"什么绝对不许进来"写成**可机检项**（扫得到、能报错），而不是文档里的一句宣言。
- **防的是**：禁入项写在开头很漂亮，后面慢慢被人破例，无人察觉。
- **怎么套**：
  ```
  禁入项：{1. 厂商自报值 / 2. 自动打分器 / 3. 跨地区公式拼接 / 4. …}
  检查方式：{扫描特征串 / 检查字段来源标记}
  命中即 FAIL，报错写明"命中禁入项 {N}"
  ```
- **误用对照**：禁入清单只写在 README 里，没有任何检查读它。

## P-13 宣称面可数

- **判据**：对外宣称的每个数字，**安装者必须自己数得出来**；数不出来的不进宣称面。新增宣称项须登记，漏登记即 FAIL。
- **防的是**：对外说"内置 N 条"，用户装完数不出来，信任崩掉。
- **怎么套**：
  ```
  宣称项登记表：（每行一条）{能力域：用哪句话宣称 | 声称的数字 | 从哪能数出来}
  断言：宣称表里的每一项，在 {产物} 中都能被独立复现
  新增能力即新增登记；未登记即 FAIL
  ```
- **误用对照**：把上游合集的条目数（不随包分发）写成自己包的宣称。

## P-14 缺口只聚合缺口

- **判据**：问题/缺口台账**只登记"不知道什么"**，不把答案混进来。
- **防的是**：台账慢慢变成知识库的劣质副本 —— 答案和问题混在一起，既不敢删也不敢信。
- **怎么套**：
  ```
  台账每行：{缺口编号 | 描述不知道什么 | 影响哪条结论 | 状态}
  禁止：在同一个台账里写完整答案（答案属于知识层）
  ```
- **误用对照**：缺口的"解决方法"越写越长，最后成了第二份知识文件。

## P-15 结构与行为分账

- **判据**：断言覆盖度报告里，**结构断言数与行为断言数分开列**，不许用结构全绿宣称行为合格。
- **防的是**：47 项断言全是"文本里有没有"，得到一个"零行为验证"却以为万事俱备的假象。
- **怎么套**：
  ```
  结构断言 {N1} 项（可机检：文本存在性/格式/一致性）
  行为断言 {N2} 项（须独立验证：动作是否发生、产物是否生成）
  N2 = 0 时，必须在报告中显式标注"行为层未覆盖"，并安排独立验证（见 SKILL.md ⑦）
  ```
- **误用对照**：把"文档里写了要登记"当成"已经登记了"的证据。

## P-16 按语义单位判，不按体量判

- **判据**：判断"变没变、缺没缺"时，比较对象必须**对齐事故的真实形态**（整节消失 / 整个对象缺失 / 关键字段被改），
  不许拿会因**合法格式变化**而变的量（字节数、文件大小、时间戳）当判据。
- **防的是**：判据天天误报 —— 真差异被淹没在噪声里，最后被人绕过或干脆关掉。
- **怎么套**：
  ```
  先写事故形态：{整节被删 / 整个对象消失 / 某关键字段被改}
  再定比较单位：{节标题集合 / 对象清单 / 关键字段值}，逐单位比对
  明确禁用：{字节数 / 文件大小 / mtime} —— 占位符化、行尾归一化、复制刷新都会让它们变
  ```
- **误用对照**：把"目标文件字节数变多"直接读成"多了内容"。实际可能是路径被替换成占位符（内容反而更短），
  也可能只是换行风格变了。**体量变了而实质没变**，是假报警最常见的来源；
  反过来，删掉一整节后补上等长的别的内容，体量不变而事故已发生 —— 这就是漏报。

## P-17 判据范围显式声明

- **判据**：判据要覆盖"哪些对象、哪些字段"必须**逐项写出来**，不许用隐式全量（"整个目录""所有文件"）代替。
- **防的是**：隐式全量把**设计**误判成**缺陷** —— 有些对象按设计本来就不该出现在比对范围里，
  不声明就无法区分"漏了"和"本来就不该有"。
- **怎么套**：
  ```
  比对范围：{显式列出的路径 / 字段清单}
  逐项声明例外与理由：{对象 A：不参与比对，理由 …；对象 B：只比存在性不比内容，理由 …}
  范围外的对象 → FAIL（fail-closed），逼着人补声明，而不是默认纳入
  ```
- **误用对照**：拿"源目录 vs 目标目录全量比对"当判据，报告里三处差异，其中两处是设计
  （某类文件按设计不复制、某目录只在目标侧生成），只有一处是真问题 ——
  但报告不区分，等于把唯一的信号埋进了噪声，看两次之后就没人看了。

## 怎么起手（建议顺序）

1. 先把 **P-01 / P-02 / P-05** 三条装上 —— 它们防的是闸门本身的三种失效（阴性失效、假闸门、漂移误报），成本最低、收益最高。
2. 再按你的领域补 **P-10 / P-11 / P-12**（判据可信度三件套）。
3. 只要你写的是**比对类**判据（比对两份内容、比对源与目标、检查"变没变"），先装上 **P-16 / P-17** ——
   它们防的是判据**自己的对齐错误**，装晚了会被误报淹没。
4. 其余按需。**不必 17 条全上**，够用即可。

## 通用提醒

- 每条断言都要能回答一句话：**"把这条检查删掉，哪一类错误会溜过去？"** 答不出来 ⇒ 这条是凑数的，删。
- 断言写完先自证：**注入缺陷 → 它报错且报对编号**。做不到的断言等于没有。
