# 分层架构与判据字段（填空模板）

> 本文件给的是**骨架和字段**，不含任何领域内容。把所有 `{花括号}` 换成你自己领域的东西即可。
> 目标：让"这条结论从哪来、还算不算数、谁能改"三件事，在任何时候都能一眼查到。

---

## 一、目录骨架（照抄改名字）

```
{专家包根}/
├── {规则文件}.md          ← L0 纪律：怎么立规则、怎么改、怎么判级
├── {索引文件}.md          ← L1 索引：有哪些权威源、各对应哪块
├── {判据文件}.md          ← L2 判据：一条条结论（干活最重的一层）
├── {场景卡片}/            ← L3 卡片：面向使用场景的整合说明
├── {证据指针}.md          ← L4 证据外置：只写"原件在哪"，不装原件
└── {评测目录}/            ← L5 评测：怎么证明这包是对的
```

**先定一件事：哪个文件是"唯一定义点"。** 每个术语、每个口径，只有一个地方写全，其他地方引用。

---

## 二、六层职责与边界

| 层 | 放什么 | 不放什么 |
|---|---|---|
| **L0 纪律** | 规则怎么立 / 怎么改 / 怎么判级的元规则；决策日志 | 任何具体专业知识 |
| **L1 索引** | 权威源清单、来源与知识块的对应关系 | 具体结论（那是 L2） |
| **L2 判据** | 可引用的一条条结论，每条带出处三件套 | 长篇解释、教学口吻 |
| **L3 卡片** | 面向场景的整合说明、选型/流程建议 | 作为最终判据依据（卡片是给人看的） |
| **L4 证据外置** | 原件/原文的**位置指针**、获取方式 | 原件本体（版权红线） |
| **L5 评测** | 检查脚本、负向用例、行为验证记录 | 业务结论 |

### 两条硬边界（越界必出乱子）

1. **规则文件、说明文件、索引文件，都不算"知识条目"。**
   对外报"知识有多少条"时，只数 L2（必要时含 L3），把文件总数报出去 = 虚报。
   *具体口径写在哪，就在这里明说，别让人去猜。*

2. **一个口径只有一处定义点。** 其他文件引用式指回。
   配套检查：文件头部声明的版本/条目数，必须等于文件末尾记录的最后一条。

## 三、判据条目字段规范（每条都填满）

```markdown
| 字段 | 填什么 | 例（结构示意，非领域内容） |
|---|---|---|
| 编号 | 唯一、稳定，永不复用 | {前缀}-{三位序号} |
| 结论 | 一句话，可判真假 | {在条件 X 下，值应取 Y} |
| 来源条款 | 权威源编号 + 条款号 | {来源编号} §{条款号} |
| 核验层级 | 见下"层级判定" | 现行有效 / 已发布未生效 / 非条文本体 / 经验值 |
| 时效戳 | 最近核验日 + 下次复核日 | {YYYY-MM-DD} → {YYYY-MM-DD} |
| 承载位置 | 这条由哪个能力域承载 | {域名称} |
| 备注 | 易错点、取值前提 | {如：原件水印压字，目测易错，须放大核对} |
```

**缺"来源条款 / 核验层级 / 时效戳"任一项，这条不算合格判据，不得进引用链。**

---

## 四、层级判定（关键：来源不定层级，内容定层级）

**不是"国标就高、企业标准就低"。** 层级 = **该文本当前的法律/效力状态**，与它出自谁、什么形式无关。

| 层级 | 含义 | 能不能进引用链 |
|---|---|---|
| **现行有效** | 已发布、已生效、未废止 | ✅ 可作依据 |
| **已发布未生效** | 发布了但生效日在未来 | ⚠️ 可预告，不得当现行依据 |
| **非条文本体** | 释义、图集、指南、教材等 | ⚠️ 可辅助理解，不作强制依据 |
| **经验值** | 实践总结、行业惯例 | ⚠️ 必须显式标注来源为经验 |
| **不入链** | 征求意见稿 / 报批稿 / 未发布 / 已废止 | ❌ 一律不引用 |

### 常见降级理由（这套已废止，别再拿它当判据）

- ❌ "出处是地方标准，所以降级" —— 不对。看它的现行状态。
- ❌ "出处是企业/团体标准，所以降级" —— 不对。同上。
- ❌ "是推荐性标准，所以降级" —— 不对。推荐性也有现行效力。
- ❌ "是电子版/复印件，所以降级" —— 不对。载体不影响力。
- ❌ "是某个人讲的，所以降级" —— 不对。看内容有无权威源支撑。

> **唯一正确的降级理由：它当前不是现行有效文本**（或属于上表"不入链"那一类）。

## 五、时效戳分档（规则只写一处）

```markdown
## 复核周期档位（唯一定义点）
- 短档：{当来源属于「全文强制性文件」时} → 每 {季度} 复核一次
- 长档：{其余全部来源，含仅部分条款强制、推荐性、产品标准、地方文件、非标准来源} → 每 {半年} 复核一次
```

**分档理由**：全强制文件改动代价高、影响面大，盯紧一点；其余来源变动频率没那么高，一年两核足够。

**执行纪律**：

- 复核 = **真的重新核一遍原文**，不是只改一下日期。
- 只改日期不动内容 = **数据造假**，比不核更糟。
- 复核安排**错峰分批**（按来源文件分批，不要按知识域分批 —— 同一份文件的条目必须同批复核）。
- 原件不在手边、无法复核时，**日期不动**，在备注里标明待核。

## 六、条件规则自失效（把"记得改"变成"自己会切"）

会随时间/状态变化的结论，写成条件式：

```markdown
{条件} → {结论}
例：{某标准换版且新版生效日已到} → {改用新版限值}
例：{某法规修订发布} → {引用修订后条款号}
```

**判据**：一条规则如果需要"人记得去改"，它就是错的写法。
**收益**：决策不再依赖某个人的记忆，谁来接手都跑得对。
