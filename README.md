# build-expert（造领域专家包）

一个 AI 智能体技能（Agent Skill）：把某个垂直领域的权威标准/规范，做成一个**能答专业问题、并且每个关键数字都查得到出处**的 AI 专家包。

## 什么时候用它

只问一句：**这个领域答错了有后果吗？**

- **有** —— 会有人照它开药、照它验收、照它起草（医疗合规、法律条文、食品安全、消防验收、工程造价、检验检测……）→ 用这套。它防的就是"看着像对的错答案"。
- **没有** —— 写文案、编故事、头脑风暴 → 别用，成本不划算，普通知识库打包就够。

## 它管什么

一个入口管全程，按"你现在处在哪一步"自动路由，不需要记流程术语：

| 阶段 | 内容 |
|---|---|
| 该不该做 | 三前提判据（权威源 / 拍板人 / 执行环境）+ 时间预算提醒；不满足就劝退或降级 |
| 怎么搭 | 知识采购（买方法不买内容、禁入清单前置）→ 分层架构（六层职责 + 单一事实源）→ 判据工程（来源 + 层级 + 时效戳） |
| 怎么不翻车 | 质量门禁（断言即验收、缺陷注入）→ 发布与同步（单一事实源、公开私有分流） |
| 怎么证明它行 | 外部对抗（多模型独立意见 + 报告逐条核真伪）→ 行为验证（双会话、测"做到没有"而非"写没写"） |
| 怎么持续 | 复盘修正（裁决可追溯、条件规则自失效）→ 教训沉淀（环境类进技能 / 领域类进手册 / 偏好类进记忆，三类分流） |

## 设计原则

- **单一入口**：按"你现在在哪一步"路由，不要求记住任何流程术语。
- **零门槛**：模板里只有两类内容 —— 原样照抄的，和 `{花括号}` 里填空的。
- **零硬编码**：核心流程不含任何本机路径、平台绑定或领域内容。任何支持 `SKILL.md` 的智能体宿主都能用；不依赖任何脚本、API Key 或第三方库。
- **只装方法，不装内容**：领域知识留在你自己的专家包里，本技能提供的是可套用的结构、判据模式和检查表。

## 三条铁律（流程内置）

1. **回读为准** —— 「命令成功了」「我改过了」都不等于状态变了，必须回头读产物。
2. **每个闸门都要证明坏的会被拦** —— 检查全绿只证明"当前内容过得了"，不证明"坏内容拦得住"。
3. **"没查出问题"之前先做阳性对照** —— 拿一个已知有问题的东西跑同一套判据，它必须报出来。

这三条各对应一类最贵的事故：**写操作 ≠ 状态变更**；**检查器 ≠ 它声称守护的性质**；**便捷信号 ≠ 权威状态**。

## 安装

把 `build-expert/` 目录整个放入你的智能体技能目录（通常是 `~/.<agent>/skills/` 或项目的 `.*/skills/`），宿主会自动按 `SKILL.md` 的 description 匹配触发。

**装完即可用，不需要任何 API Key、脚本或额外依赖。**

## 文件构成

- `SKILL.md` — 技能本体：三道关（该不该做 / 怎么走 / 怎么不翻车）+ 九环节流水线 + 常见误区
- `references/knowledge-architecture.md` — 分层架构、判据字段、层级判定与时效戳档位的填空模板
- `references/assertion-patterns.md` — **17 条断言模式**（每条含判据、防什么、怎么套、误用对照）
- `references/checklists.md` — **三张检查表**：开工前 8 问 / 动手改前 3 问 / 收工前 10 条

## 一句话提醒

**最大的复用风险，是把某个项目跑出来的过程文档当模板直接抄。** 那些是演进史，里面大量中间态和已废弃方案。模板要从方法内核重新提炼 —— 本技能即为该提炼的成品。
